# RAG-CMS 第 5 周补齐计划｜2026-08-30 至 2026-09-06

## 本周唯一主目标

补齐 RAG-CMS 的最小容器运行边界：镜像只包含应用和依赖，模型配置在运行时注入，文档数据持久化挂载，并以 `/health` 验证 API 进程。

## 当前起点

- Python 本地启动和 Java → Python 契约已通过；
- Dockerfile、Compose 和容器验证此前缺失；
- 当前主机仍无 `docker` 命令，因此静态制品与真实启动必须分层记录；
- 第 30 天检查仍因 Docker 验收和知识卡数量不足而逾期。

## 项目时段任务

- [x] 第 1 次（8月30日）：定义镜像、运行配置、数据卷和健康检查边界
- [x] 第 2 次（9月1日）：完成 Dockerfile、Compose、`.dockerignore` 与静态契约测试
- [ ] 第 3 次（9月3日）：在具备 Docker 的环境构建镜像并验证 `/health`
- [ ] 第 4 次（9月5日）：验证数据卷持久化与未配置模型时的 503 边界
- [ ] 第 5 次（9月6日）：完成复盘、容器架构案例和理解检查

## 本周不做

- 不在镜像中写入 `.env`、API Key 或运行数据；
- 不引入 Kubernetes、CI/CD、反向代理或容器编排平台；
- 不借 Docker 接入未经授权的真实模型；
- 不把静态文件检查描述为容器启动验收；
- 不扩展 PDF/Word、Rerank 或问答日志。

## 验收标准

1. 镜像使用与项目一致的 Python 3.9；
2. 容器以非 reload 模式监听 `0.0.0.0:8000`；
3. `.env`、`.venv` 和 `data/` 不进入构建上下文；
4. 模型配置由运行环境注入；
5. `data/` 通过挂载跨容器保存；
6. 实际容器的 `/health` 返回 200 后，才能判定启动验收完成。

## 阻塞处理

本机无 Docker 时先完成第 1～2 次并保留第 3～4 次未勾选；安装或获得可用 Docker 环境后继续，不以静态检查替代运行证据。
