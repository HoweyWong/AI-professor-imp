# RAG-CMS 最小价值证据实验｜执行模板

## 1. 实验问题

在指定 CMS 文档与 5～10 个真实问题范围内，RAG-CMS 是否能在答案和引用被人工接受的前提下，减少完成一次文档查找任务的总耗时？

本实验不证明组织级 ROI，也不比较不同公司、岗位或模型。

## 2. 运行前授权

以下字段全部确认后才能开始真实运行：

| 字段 | 填写内容 |
|---|---|
| 文档名称或受控代号 | 待确认 |
| 文档所有者 | 待确认 |
| 数据敏感级别 | 待确认 |
| 是否允许进入本地 RAG-CMS | 待确认 |
| 是否允许发送给当前 Embedding 服务 | 待确认 |
| 是否允许发送检索片段给当前 LLM | 待确认 |
| 模型服务归属与处理约定 | 待确认 |
| 参与者 | 待确认 |
| 实验日期 | 待确认 |

任一项为“不允许”或“不明确”时，停止外部调用；可以改用已公开固定语料做流程演练，但不得记为真实业务价值。

## 3. 样本选择

- 数量：5～10 题；
- 来源：参与者近期真实查过或将要查的 CMS 任务；
- 覆盖：直接事实、跨段汇总、条件/例外、不可回答至少各 1 题；
- 排除：答案已被参与者熟记、文档无权使用、问题只能依赖文档外知识；
- 冻结：运行前固定问题与文档，不因结果不好替换样本。

## 4. 顺序控制

同一问题不能总是先人工、后 RAG，否则第二次会因记住答案而更快。

- 奇数题：人工方式 → 间隔后 RAG；
- 偶数题：RAG 方式 → 间隔后人工；
- 每种方式开始前不查看另一种方式的答案与依据；
- 若无法做到隔离，在限制中明确记录学习效应，不做强因果结论。

## 5. 计时边界

### 人工方式

从看到问题开始，到提交“答案 + 文档依据位置”为止，包括打开、搜索、阅读和核对文档。

### RAG 方式

从看到问题开始，到提交“是否接受答案 + 完成引用回查”为止，包括输入问题、等待、阅读和核对引用。接口延迟另记，但不能替代总任务耗时。

## 7. 汇总规则

- 分别报告人工与 RAG 总耗时的中位数，不用小样本平均数掩盖极端值；
- 报告 RAG 答案接受数、引用支持数和各类失败数；
- 逐题列出节省或增加的时间，不只给一个汇总百分比；
- 若 RAG 更快但答案或引用不接受，不计为有效节省；
- 若样本不足 5 题，只作为流程演练，不下价值结论。

## 8. 结论模板

```text
在【参与者】使用【文档范围】完成【N】个问题时，
人工任务耗时中位数为【】秒，RAG 任务耗时中位数为【】秒；
RAG 答案接受【】/【N】，引用支持【】/【N】，失败【】次。
因此，本次证据【支持 / 不支持 / 尚不足以判断】
RAG-CMS 在该局部场景中减少可接受答案的查找时间。
该结论不外推到其他用户、文档、模型或组织 ROI。
```

## 9. 三个必须保留的实验结果

1. 正常路径：至少一题答案和引用均接受；
2. 参数或场景变化：直接事实与跨段问题各至少一题；
3. 失败案例：真实记录一题不接受、不可回答或技术失败；若没有自然失败，不人为伪造，只记录“本样本未观察到”。
