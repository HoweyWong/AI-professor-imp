# 开发环境前后端部署关键命令

> 适用服务器：`VDHQNCMSPLATFORM01` / `10.64.161.11`  
> 适用场景：`my-modules-system`、`cms-algorithm` 和 `cms-vue3` 日常更新  
> Nacos命名空间：`dev-major`

## 1. 本地构建

### 1.1 基座和系统服务

公共模块有修改时必须先执行 `install`，防止独立业务服务嵌入旧的 `.m2` 依赖。

```powershell
cd D:\03soft\codeCenter\cms\cms-health-platform
mvn -pl my-modules/my-system -am clean install -DskipTests
```

系统服务产物：

```text
cms-health-platform\my-modules\my-system\target\my-modules-system.jar
```

### 1.2 算法服务

```powershell
cd D:\03soft\codeCenter\cms\cms-algorithm
mvn clean package -DskipTests
```

算法服务产物：

```text
cms-algorithm\target\cms-algorithm.jar
```

### 1.3 前端

开发环境Nginx代理前缀为 `/stage-api`，必须使用 staging 构建：

```powershell
cd D:\03soft\codeCenter\cms\cms-vue3
npm run build:stage
```

前端产物：

```text
cms-vue3\dist
```

不要使用 `npm run build:prod`，否则接口前缀为 `/prod-api`，当前Nginx会返回405。

### 1.4 本地哈希

```powershell
Get-FileHash -Algorithm SHA256 `
  D:\03soft\codeCenter\cms\cms-health-platform\my-modules\my-system\target\my-modules-system.jar

Get-FileHash -Algorithm SHA256 `
  D:\03soft\codeCenter\cms\cms-algorithm\target\cms-algorithm.jar
```

## 2. 上传

通过JumpServer文件管理上传到一个独立临时目录，例如：

```text
/tmp/projectIn-YYYYMMDD-deploy/
├── my-modules-system.jar
├── cms-algorithm.jar
└── dist/
```

上传完成后：

```bash
UPLOAD_DIR=/tmp/projectIn-YYYYMMDD-deploy
find "$UPLOAD_DIR" -maxdepth 2 -printf '%M %u:%g %s %p\n' | sort
sha256sum "$UPLOAD_DIR/my-modules-system.jar"
sha256sum "$UPLOAD_DIR/cms-algorithm.jar"
test -f "$UPLOAD_DIR/dist/index.html" && echo 'dist/index.html OK'
test -d "$UPLOAD_DIR/dist/static" && echo 'dist/static OK'
```

服务器哈希必须与本地一致。

## 3. 服务器更新系统服务

```bash
RELEASE_ID=$(date +%Y%m%d-%H%M%S)
UPLOAD_DIR=/tmp/projectIn-YYYYMMDD-deploy

SYSTEM_HOST_DIR=/home/cms/docker/my/modules/system/jar
SYSTEM_CONTAINER=my-modules-system

# 备份并更新宿主机构建目录
cd "$SYSTEM_HOST_DIR"
sudo cp -a my-modules-system.jar \
  "my-modules-system.jar.backup-$RELEASE_ID"
sudo cp -a "$UPLOAD_DIR/my-modules-system.jar" my-modules-system.jar
sudo chown cms:cms my-modules-system.jar
sudo chmod 755 my-modules-system.jar

# 备份并更新运行容器
sudo docker exec "$SYSTEM_CONTAINER" \
  cp /home/my/my-modules-system.jar \
  "/home/my/my-modules-system.jar.backup-$RELEASE_ID"
sudo docker cp "$UPLOAD_DIR/my-modules-system.jar" \
  "$SYSTEM_CONTAINER:/home/my/my-modules-system.jar"
sudo docker exec "$SYSTEM_CONTAINER" chmod 755 /home/my/my-modules-system.jar

# 核对、重启、查看日志
sudo docker exec "$SYSTEM_CONTAINER" sha256sum /home/my/my-modules-system.jar
sudo docker restart "$SYSTEM_CONTAINER"
sudo docker ps | grep "$SYSTEM_CONTAINER"
sudo docker logs --tail=300 "$SYSTEM_CONTAINER"
```

## 5. 服务器更新前端

```bash
NGINX_HTML=/home/cms/docker/nginx/html

sudo docker stop my-nginx

cd "$NGINX_HTML"
sudo mv dist "dist-old-$RELEASE_ID"
sudo cp -a "$UPLOAD_DIR/dist" "$NGINX_HTML/dist"
sudo chown -R cms:cms "$NGINX_HTML/dist"

test -f "$NGINX_HTML/dist/index.html" && echo 'index.html OK'
test -d "$NGINX_HTML/dist/static" && echo 'static OK'

sudo docker start my-nginx
sudo docker ps | grep my-nginx
sudo docker logs --tail=200 my-nginx
```

## 6. 最终验证

```bash
sudo docker ps \
  --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}' \
  | grep -E 'NAMES|my-modules-system|cms-algorithm|my-nginx'

curl -I --max-time 10 http://127.0.0.1/
curl -i -X DELETE --max-time 10 \
  http://127.0.0.1/stage-api/auth/logout
```

浏览器执行 `Ctrl+F5` 后验证：

- 登录和退出；
- 项目列表、详情和设备数据；
- 人员、组织选项；
- 项目ID在原始Response中是带引号的字符串；
- Network无新增404、405、502或503。

## 7. 关键注意事项

- 基座公共模块变更后：先在 `cms-health-platform` 执行 `clean install`，再打包 `cms-algorithm`。
- 系统和算法JAR复制到容器后只需重启；宿主机构建目录也要同步，防止以后重建镜像恢复旧包。
- 删除并重建容器时，必须重新构建包含新JAR的镜像。
- 开发环境前端固定执行 `npm run build:stage`。
- 不执行包含 `DROP TABLE` 的 `xmzr_alter.sql`。
- 任一服务启动失败时停止后续发布，先查看日志并回滚对应备份。
