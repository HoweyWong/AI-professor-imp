# CMS 发布与回滚指南

## 发布窗口

生产环境固定发布窗口为每周二和周四 21:00–22:00。紧急安全修复可以申请窗口外发布，但必须获得值班经理和系统负责人的共同批准。普通功能不得使用紧急发布流程。

## 发布前检查

发布申请至少提前一个工作日提交。发布前必须完成单元测试、接口回归测试和数据库备份，并确认监控面板无未处理的 P1 告警。涉及数据库结构变更时，还必须附带经过验证的回滚 SQL。

发布包必须带有唯一版本号，格式为 `cms-YYYYMMDD-N`。同一个版本号不得重复用于不同构建产物。

## 执行与观察

发布由两人协作执行：一人操作，一人复核。部署完成后先检查健康接口，再执行三条核心业务冒烟用例。全部通过后进入 30 分钟观察期。观察期内重点关注 HTTP 5xx 错误率、接口 P95 延迟和数据库连接池使用率。

## 回滚条件

满足以下任一条件必须回滚：连续 5 分钟 HTTP 5xx 错误率高于 2%；核心接口 P95 延迟高于 800 毫秒；核心业务冒烟用例失败；出现数据写入错误。

回滚时先停止新流量，再恢复上一版本应用。若本次发布包含数据库结构变更，则执行已验证的回滚 SQL。回滚完成后重新检查健康接口，并在 30 分钟内提交事故初报。

## 数据与权限

生产数据库备份保留 30 天。发布人员只能使用个人账号操作，禁止共享账号。本文没有规定测试环境的发布窗口，也没有规定移动端应用的发布流程。
