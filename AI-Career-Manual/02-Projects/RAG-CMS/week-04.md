# RAG-CMS 第 4 周补齐计划｜2026-08-23 至 2026-08-30

## 本周唯一主目标

完成 Java 调用 Python 文档问答接口的最小闭环，让现有 Java 业务系统能够获得答案与可追溯引用，并能区分上游失败、服务不可用和超时。

## 当前起点

- Python `/v1/documents/{document_id}/questions` 已返回 `question`、`answer` 和 `citations`；
- Java 11 与 Maven 可用，本地已有 Spring Boot 2.7.18 WebFlux 依赖；
- 当前没有 Java 客户端工程、DTO、错误映射或集成测试；
- Docker 不可用，本周不与 Java 集成同时补齐。

- [x] 第 1 次（8月23日，周日）：建立 Java 11 Maven 模块，定义问题、回答和引用 DTO

- [x] 第 3 次（8月27日，周四）：使用本地假服务验证成功响应、引用映射、502、503 和超时
- [x] 第 4 次（8月29日，周六）：追踪真实本地 Java→Python 请求，记录三类实验并更新 README
- [x] 第 5 次（8月30日，周日）：完成 Week 4 复盘、架构案例与理解检查

## 本周不做

- 不重写 Python RAG 实现；
- 不引入服务注册、网关、鉴权、重试框架或熔断组件；
- 不调用未获授权的外部模型服务；
- 不同时实现 Docker、PDF/Word 或问答日志；
- 不只返回答案字符串而丢弃引用。

## 验收标准

1. Java 11 可以编译并运行最小客户端；
2. 请求 DTO 正确发送 `question` 和 `top_k`；
3. 响应 DTO 保留答案及引用的文档、Chunk、偏移和相似度；
4. 502、503、超时和一般传输失败可以被业务代码区分；
5. 本地假服务测试不访问真实模型；
6. 至少一条本地 Java→Python 请求完成约定场景验证。

## 周末滚动规则

- 用户确认每次验收后才勾选；
- Java 最小闭环完成后再安排 Docker；
- 从 Java/Python 接口边界提炼一篇架构案例和 1～2 张知识卡；
- 未完成项顺延，不用扩展新功能补偿进度焦虑。
