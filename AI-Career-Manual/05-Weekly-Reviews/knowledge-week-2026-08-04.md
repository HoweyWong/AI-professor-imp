# 知识储备周计划｜2026-08-04 至 2026-08-10

## 本周唯一知识主题

RAG 评测：检索 Recall@K、答案要点覆盖与引用忠实性。

## 核心问题

如何把“回答看起来不错”拆成可观察、可重复、可定位故障的三层指标？

## 本周任务

- [ ] 用自己的话区分检索召回、答案覆盖和引用忠实性
- [ ] 完成 1 张知识卡：RAG 分层评测与故障定位
- [ ] 在 RAG-CMS 中实际计算 Recall@1 和 Recall@3
- [ ] 8月9日（周日）复盘：记录参数实验、失败案例和 Week 3 唯一知识主题

## 输入、处理与输出

```text
固定语料 + 结构化问题 + 期望依据
→ Top-K 检索 → 要点与引用判定 → 分层汇总
→ Recall@K + 回答覆盖结果 + 引用忠实性结果
```

## 与 Java / Spring 的对照

- 相似点：类似参数化集成测试，以固定 fixture、输入和分层断言形成回归基线；
- 限制：生成结果存在随机性，不能只用字符串相等或一次运行判断稳定性；
- 工程启发：先把检索这种确定性较强的部分自动化，再逐步处理生成质量评分。

## 本周不做

- 不把阅读材料数量作为完成标准
- 不在没有固定基线时比较多个模型

至少完成 1 张知识卡、1 组 Recall@K 实验和 1 个失败案例定位，并能从“正确依据是否召回”处分流排查。
