## 三个实验

### 实验 1｜正常路径

- 改变什么：从无运行时环境到安装 Colima 并实际构建；
- 观察什么：容器 `healthy`，`/health` 返回 200；
- 结论：Docker 启动形成真实闭环，不再只是静态文件。

### 实验 2｜生命周期变化

- 改变什么：上传固定文档后强制重建容器；
- 观察什么：挂载的元数据文件哈希不变；
- 结论：该测试数据独立于旧容器生命周期，但哈希不证明语义正确。

### 实验 3｜典型失败

- 改变什么：一是容器刚 running 就访问；二是不注入模型变量；
- 观察什么：前者在 `health: starting` 时出现空响应，后者容器健康但问答返回 503；
- 结论：running、healthy 和问答 ready 是三个不同层次。

## 安装影响与回归

Homebrew 自动清理了部分旧缓存、Python 3.13 和旧 OpenJDK 20 formula。项目 `.venv` Python 3.9.6、系统 Java 11、Python 28 项测试和 Java 测试均通过。Maven 当前仍报告既有 JDK 20 路径，后续需显式统一 Java 11，避免 Homebrew 链接变化。

## 与 Java / Spring 的对照

- 镜像对应固定 JRE、JAR 和启动命令；
- 环境变量对应外部化配置；
- 数据卷对应应用进程之外的持久化资源；
- `/health` 类似 liveness，而非完整业务 readiness；
- 类比边界：本地文件挂载不具备数据库的一致性、并发和备份能力。

## 本周最大问题与根因

最大问题是首次重建后在 `health: starting` 阶段立即访问，得到空响应。根因是把“容器进程已创建”误作“应用已就绪”。改为 Compose `--wait`，由健康条件驱动后续验证。
