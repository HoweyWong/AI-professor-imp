## 真实数据链路

```text
Java contract-document + “发布前做什么？” + topK=1
→ RagCmsClient / QuestionRequest
→ HTTP POST 127.0.0.1:18080
→ FastAPI /v1/documents/{document_id}/questions
→ 本地替身 Embedding [1.0, 0.0]
→ 本地替身 Top-1（chunk=2、offset=20..34、score=0.91）
→ 本地替身回答“完成回归测试。[来源 1]”
→ FastAPI answer + citations JSON
→ Java QuestionResponse + Citation
```

链路中的 HTTP、FastAPI 路由、Pydantic 校验、Prompt 构造、引用映射和 Java DTO 是真实执行的；Embedding、检索与回答模型是固定本地替身，没有外部调用。

## 三个实验

### 实验 1｜正常路径

- 改变什么：Java 客户端调用真实 FastAPI 路由，不使用 Java 内置假服务；
- 观察什么：答案、reference、文档、Chunk、偏移和分数全部进入 Java DTO；
- 结论：当前 Java/Python JSON 契约可以跨语言闭环。

### 实验 2｜参数边界

- 改变什么：`top_k` 从 1 改为 11；
- 观察什么：FastAPI 在进入 Embedding、检索和模型替身前返回 422；
- 结论：Java 本地校验改善调用体验，Python 服务端校验仍是最终防线。

### 实验 3｜典型失败

- 改变什么：假服务分别返回 502/503、延迟超过截止时间、关闭监听端口；
- 观察什么：Java 映射为 `UPSTREAM_FAILURE`、`SERVICE_UNAVAILABLE`、`TIMEOUT`、`TRANSPORT`；
- 结论：同为“问答失败”，故障位置和后续动作不同，不能统一吞成一个异常。

## 失败案例

最初用端口 1 模拟连接拒绝，在当前 macOS/Netty 环境出现异常 DNS 路径并表现为超时。改为“启动随机端口 → 关闭 → 连接已知关闭端口”后稳定得到 `TRANSPORT`。根因不是业务代码，而是失败实验输入不能稳定代表目标故障。

## 与 Java / Spring 的对照

- 请求/响应 DTO：跨服务契约；
- `RagCmsClient`：基础设施适配器；
- `FailureType`：异常翻译层；
- Java 假服务测试：客户端组件测试；
- Java → FastAPI 测试：跨语言契约测试；
- 类比边界：同步 `block()` 不适合直接放入完整 WebFlux 事件循环，结构正确也不代表 RAG 回答忠实。

## 本周最大问题与根因

最大问题是容易把不同层级的“通过”混为一谈。根因是同一请求跨越 Java、HTTP、Python、检索和模型。解决方式是给测试结论附上边界：假服务验证 Java，真实路由替身验证契约，真实模型与数据另行验收。
