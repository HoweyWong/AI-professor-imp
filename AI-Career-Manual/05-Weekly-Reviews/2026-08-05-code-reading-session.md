# 2026-08-05｜RAG-CMS 代码阅读复述记录

## 今日主目标

以 Java / Spring 开发经验为参照，理解 RAG-CMS 的模块职责、向量比较条件、生成侧故障定位和当前存储方案的工程边界。

## 用户复述与反馈

### 1. 模块职责

用户已能将：

- `documents.py` 理解为文档解析服务及文件存储 Repository；
- `vectors.py` 理解为向量化编排及向量保存 Repository；
- `retrieval.py` 理解为余弦相似度和 Top-K 召回服务。

补充：当前 Python 文件为了保持最小实现，Service 与 Repository 尚未严格分层；迁移到 Spring 时可以拆开。

### 2. Embedding 模型一致性

用户已理解只有遵循同一套向量规则才有比较意义。

纠正：相似度比较发生在“问题向量”和“文档 Chunk 向量”之间，而不是问题与答案之间；维度相同只是必要条件，不是充分条件。二者还必须由同一 Embedding 模型生成，处于同一语义坐标空间。

### 3. 正确 Chunk 已召回后的排查

用户能定位到 Prompt 和模型幻觉。

补充检查顺序：上下文拼接是否完整 → Prompt 是否清晰 → 模型是否忠于依据 → `[来源 N]` 与 citation 映射是否正确。

### 4. JSON 向量存储的生产边界

用户已认识到缺少正式数据库、工程化保证和安全能力。

补充：当前还存在全量扫描 `O(Chunk 数 × 向量维度)`、并发写覆盖、无事务、无索引、全量加载内存、无权限过滤及多实例文件一致性等限制。
