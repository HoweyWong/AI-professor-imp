# 架构案例执行计划｜90 天

## 定位

架构案例是 RAG-CMS 主线的复盘产物，不是新的并行项目。优先从当周真实问题中提炼，控制在 30～45 分钟内完成。

## 目标

- 目标数量：10
- 执行频率：原则上每周 1 篇，90 天内允许 3 周因项目验收跳过
- 验收底线：至少写清一个关键取舍、一个风险限制和一个可迁移到当前项目的动作
- 完成规则：案例文件形成并经用户确认后，才勾选对应任务

## 下一项

- [x] 2026-08-23 前：完成《RAG 四层评测体系｜如何区分相关性、充分性、答案覆盖与引用忠实性》
- [ ] 2026-08-30 前：完成《Java 调用 Python AI 服务｜接口契约与故障边界》

## 最小执行步骤

1. 用 5 分钟写业务问题、现状和核心约束；
2. 用 20 分钟画数据流并写方案、关键取舍和风险；
3. 用 10 分钟写一个能进入 RAG-CMS 的具体改进行动；
4. 用 `case-template.md` 自检，未写取舍或行动则不算完成。

## 待选题池

最多保留 3 项，完成当前案例后再选择下一项：

1. RAG 评测运行如何绑定语料、模型、Prompt 与参数版本；
2. Java 调用 Python AI 服务时如何划分接口与故障边界；
3. AI 问答日志如何兼顾审计、隐私与可观测性。

## 与主线的边界

- 不为写案例暂停当前项目验收；
- 不同时研究多个新技术主题；
- 不把技术摘要当成架构案例；
- 用户未确认前不勾选任务。
