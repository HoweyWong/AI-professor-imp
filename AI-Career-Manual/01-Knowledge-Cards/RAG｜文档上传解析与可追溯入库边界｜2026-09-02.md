# RAG｜文档上传、解析与可追溯入库边界｜2026-09-02

## 所属主线

AI 应用架构

## 核心结论

RAG 文档入库不是“把一段文本写入磁盘”，而是同时保留原始输入、规范化文本和可追溯元数据。上传校验只能建立最低输入边界，不能替代文件真实性、权限、版本和恶意内容治理。

## 问题背景

切分、Embedding、检索和引用都依赖文档入库结果。如果只保存解析文本，后续无法回查原文件；如果只保存原文件，下游每次都要重新解析；如果没有元数据，文件、文本、Chunk 和引用之间无法稳定关联。

## 输入、处理与输出

```text
UploadFile
→ 扩展名、大小、UTF-8、非空校验
→ UUID document_id
→ source.md/txt（原始字节）
+ content.txt（规范化文本）
+ metadata.json（身份、来源、大小、路径和时间）
→ Chunk / Embedding / 检索 / Citation
```

## 关键机制

- 扩展名白名单：`.md`、`.markdown`、`.txt`；
- 大小限制：读取最多 `5 MiB + 1 byte`，超过即返回 413；
- 编码校验：原始字节必须能按 UTF-8 解码；
- 语义最低线：空文件或全空白文本拒绝入库；
- 身份隔离：UUID 作为文档目录和后续链路主键；
- 双份保存：原始字节用于审计，`content.txt` 用于确定性下游处理；
- 元数据：保存原文件名、MIME 声明、字节/字符数、UTC 时间和相对路径。

## 项目中的实际数据链路

```text
POST /v1/documents（README.md）
→ HTTP 201
→ data/documents/{document_id}/source.md
→ data/documents/{document_id}/content.txt
→ data/documents/{document_id}/metadata.json
→ chunks.json → vectors.json → citations.source_path
```

Docker 验收进一步证明 `data/` 挂载在容器重建前后保留了目标元数据文件；文件哈希一致只说明字节未变化，不证明元数据语义正确。

## 适用条件

- 首期只处理小型 Markdown 和 UTF-8 文本文档；
- 单机文件存储足以支撑学习和最小闭环；
- 文档进入系统前已通过业务侧授权。

## 限制与风险

- 扩展名和客户端 MIME 都不能证明真实文件类型；
- 没有恶意内容扫描、租户隔离、访问控制和配额；
- UUID 避免普通命名冲突，不识别重复内容，也不形成版本关系；
- 本地文件写入不是事务，进程中断可能留下部分文件；
- 解析仅支持 UTF-8 文本，PDF/Word 尚未实现；
- `data/` 不进 Git 不等于已经具备备份、加密和删除策略。

## 参数实验与结论

- 正常 `.md`：返回 201，并生成原文件、文本和元数据；
- `.env.example`：扩展名不在白名单，返回 415；
- 容器强制重建：目标元数据哈希保持一致，证明该文件由挂载目录保留；
- 边界推论：若仅把 `.exe` 改名为 `.txt`，扩展名检查可能通过，但 UTF-8 解码或内容治理仍可能失败，不能把白名单称为文件真实性校验。

## 一个失败案例

把文件扩展名白名单解释为“安全文件类型检测”。扩展名由上传者控制，MIME 也可能伪造；它只能限制当前解析分支，不能证明内容安全或格式真实。

## 与 Java / Spring 的对照

`UploadFile` 类似 Spring `MultipartFile`；Pydantic/FastAPI 路由与保存函数分别对应 Controller 校验和应用 Service。当前直接使用 `Path` 写文件，类似最小本地 Repository。边界是 Java 类型系统和 Bean Validation 同样不能替代内容嗅探、病毒扫描、授权和事务存储。

## 对当前项目的启发

在增加 PDF/Word 前，先定义统一的解析结果契约和文档版本/权限字段；只有多租户或生产试用进入范围时，再引入对象存储、数据库事务和安全扫描。

## 可验证行动

为 `save_document` 补充正常、超限、非 UTF-8、空白和伪扩展名测试；真实内容检测与权限隔离另立需求，不混入当前最小闭环。

## 我能否脱离代码讲清楚

- 为什么需要它：为所有下游 Chunk、向量和引用保留可信的输入链；
- 输入和输出：上传字节进入校验，输出原文件、规范文本和元数据；
- 失败时先检查：状态码、扩展名、大小、编码、空白，再查文件写入；
- 仍未理解的问题：如何让三文件写入具备原子性并安全处理重复版本。
